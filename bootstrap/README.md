# M0.0 Engineering Bootstrap — Shadow Mode

This directory contains a small, replaceable gate for repository engineering. It does not implement Hayool V1.0 product behavior. The kill switch disables autonomous writes, merge, deployment and external calls. No production credentials are present.

`baseline.py` checks V7.2 source archive integrity, isolated candidate tests, workflow/security policy, dependency manifests, planned license pins, tracked-file secret patterns, protected test/gate changes and PR traceability. A candidate test runs in a pinned Python container with a read-only checkout, no network or inherited secrets, non-root identity, limited CPU/memory/processes/output and a 90-second timeout. A missing or failed container is a hard failure. `regression_tests/test_unit_boundary.py` reproduces the original in-process exploit in a disposable fixture and proves the new process boundary.

`.github/workflows/engineering-baseline.yml` is the read-only `pull_request` seed job for PR #1. Its result is **not a trust anchor** because a PR can edit that workflow. `.github/workflows/engineering-trusted-gate.yml` is the protected-main `pull_request_target` workflow. Its read-only candidate job runs base policy and isolated candidate tests; its separate status-writing job checks out only main, authenticates run/artifact/PR provenance, preserves its own report, then posts `engineering-trusted-gate-status` to the exact head. Repository Actions policy 5892 is staged disabled; after an independent seed merge it must be activated to allow only `pull_request_target` for all workflow paths, blocking PR-controlled same-App check spoofing. Branch protection must then require the posted status. ADR-033 and `docs/engineering/TRUSTED_CI_ARCHITECTURE.md` record the activation and live attack proof required before M0.0 can pass.

`engrun.schema.json` describes a single `ENG-RUN-*` record. One writer owns one `codex/*` branch for at most one hour. At least two independent reviewers are read-only and bind reports and severity findings to the same exact head SHA. The evaluator rejects open P0/P1 even if the reviewer votes PASS, stale base/head/policy SHA, risk below the deterministic path classification, missing or failed hard checks, unauthenticated protected-main GitHub CI, inactive event policy, changed evidence hashes, unverified provider/model identity, expired lease, more than three repairs, more than 60 minutes, external cost above the zero-dollar cap, an engaged kill switch, or any claimed merge/deployment in Shadow Mode. Model votes cannot override a hard failure.

For a Shadow PR after the seed merge, record exact base/head/policy SHA and changed paths; run the protected-main GitHub workflow; verify both artifacts and the server-side policy/status readback; obtain two independent read-only reviews of the same exact SHA; then evaluate ENG-RUN. A new commit invalidates affected checks and reviews. Keep failed injections and repair outcomes with actual run IDs. The current GitHub account/branch situation and independent human merge hold are tracked in `PROJECT_STATE.md`, `NEXT_ACTIONS.md`, and `docs/evidence/EVIDENCE_INDEX.md`.
