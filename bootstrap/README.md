# M0.0 Engineering Bootstrap — Shadow Mode

This directory contains a small, replaceable gate for repository engineering. It does not implement Hayool V1.0 product behavior. The kill switch disables autonomous writes, merge, deployment and external calls. No production credentials are present.

`baseline.py` checks V7.2 source archive integrity, isolated candidate tests, workflow/security policy, dependency manifests, planned license pins, tracked-file secret patterns, protected test/gate changes and PR traceability. A candidate test runs in a pinned Python container with a read-only checkout, no network or inherited secrets, non-root identity, limited CPU/memory/processes/output and a 90-second timeout. A missing or failed container is a hard failure. `regression_tests/test_unit_boundary.py` reproduces the original in-process exploit in a disposable fixture and proves the new process boundary.

`.github/workflows/engineering-baseline.yml` is a read-only `pull_request` candidate job. Its result is **not a trust anchor** because the PR can edit its workflow. `.github/workflows/engineering-trusted-gate.yml` is a `workflow_run` verifier that GitHub loads from protected default `main` once PR #1 has been independently reviewed and merged. It runs only default-branch policy, treats candidate artifacts as untrusted data, verifies exact GitHub run and policy provenance, and publishes `engineering-trusted-gate-status` for the head only after success. The first import from README-only `main` is a bootstrap exception; current candidate CI alone cannot close M0.0. ADR-032 and `docs/engineering/TRUSTED_CI_ARCHITECTURE.md` give the boundary and server-side activation conditions.

`engrun.schema.json` describes a single `ENG-RUN-*` record. One writer owns one `codex/*` branch for at most one hour. At least two independent reviewers are read-only and bind reports to the same exact head SHA. The evaluator rejects a stale base/head/policy SHA, risk below the deterministic path classification, missing or failed hard checks, unauthenticated GitHub candidate or trusted CI, changed evidence hashes, unverified provider/model identity, expired lease, more than three repairs, more than 60 minutes, external cost above the zero-dollar cap, an engaged kill switch, or any claimed merge/deployment in Shadow Mode. Model votes cannot override a hard failure.

For a Shadow PR, record the exact base/head/policy SHA and changed paths; run GitHub CI; download and hash its artifact; verify the trusted default-branch gate run; obtain two independent read-only reviews of the same exact SHA and evidence; then evaluate ENG-RUN. A new commit invalidates affected checks and reviews. Keep failed injections and repair outcomes with actual run IDs. The current GitHub account/branch situation and the independent human merge hold are tracked in `PROJECT_STATE.md`, `NEXT_ACTIONS.md`, and `docs/evidence/EVIDENCE_INDEX.md`.
