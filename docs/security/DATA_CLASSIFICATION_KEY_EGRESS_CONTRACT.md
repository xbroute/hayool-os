# Data classification, encryption and egress contracts

Status: specified V1.0. REQ-TRU-001 classifies/minimizes data and purpose, REQ-TRU-019 owns customer-data encryption/key lifecycle, REQ-TRU-020 prevents unauthorized sink egress. Vault secret retrieval/rotation remains separate REQ-TRU-013. Each has its own TEST ID and approval boundary; no blanket security-certification claim follows from these documents.

Classification records data class, field/derived lineage, tenant/entity, purpose, legal retention and processing region, approved collectors and sinks with version. Unknown sensitive class is denied/pending before collection or dispatch. Encryption protects transport, database/object/backups and selected restricted fields using scoped key-encryption/data keys, versioned grants, rotation and separate recovery material. A key cannot be restored from a data backup alone; an unrecoverable or revoked key stops dependent access with incident and recovery workflow. Egress is checked before logging, trace sampling, browser response, prompt/retrieval context, support export and external processor call; redaction at source and sink, including exception and replay, is required.

`TEST-REQ-TRU-001`: add unnecessary sensitive field and derived summary; neither enters approved data store or export without purpose/version approval. `TEST-REQ-TRU-019`: rotate, revoke, wrong-tenant/region decrypt, partial failure, backup restore and missing key; authorized data remains readable only with correct recoverable keys and plaintext never leaks into diagnostic artifacts. `TEST-REQ-TRU-020`: separate credential and personal-data sentinels through success/error/retry/AI-off traces, browser, support export and model context; all unauthorized sinks remain empty. Verify independent TEN/SEC/OPS/AI evidence on exact build/config.
