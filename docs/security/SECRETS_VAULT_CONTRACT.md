# Secrets Vault — independent security contract

Owner: Security/Secrets service, REQ-TRU-013, ADR-029, TEST-REQ-TRU-013 and VLT suite. A reference is an opaque scoped identifier and metadata; raw secret bytes live only in a dedicated supported vault/key boundary. Asset, workflow, integration and app records hold references, never raw values. Tenant, environment (dev/test/staging/prod), legal entity, purpose, app/service principal and permitted capability bound to grant. Production secrets never enter synthetic test tenants.

Secret lifecycle: `proposed -> created/imported -> active -> rotating -> revoked/expired -> destroyed per retention`; version and rotation overlap are explicit. Least-privilege short-lived capability retrieval or delegated operation (sign, send, connect) is preferred to revealing bytes. Access checks authenticate principal, tenant/entity, environment, intended provider/action, policy epoch and expiry at invocation; a revoked grant cannot be resurrected by cached job or backup. Break-glass has dual/time-bound approval, audit, review and emergency rotation plan. Secret manager policy is independent of app UI role. Vault outage blocks protected external dispatch and records actionable incident; read-only asset register remains available.

No plaintext secret in general AI context, browser storage or response, URLs, exceptions, telemetry, analytics, support export, prompt, CI artifact or logs. Browser actions invoke a scoped server-side capability without receiving the secret bytes. Any extraordinary human reveal needs a separate explicitly authorized, time-bound security policy and cannot be inferred from ordinary asset access or app installation. Masking is defense in depth; redaction and egress tests use sentinel credentials. Credential metadata (owner/provider/expiry/rotation due) may support asset reminders under ACL. Provider/BYOK adapters receive capability not unrestricted store access; environment and region policy gates still apply.

TEST-REQ-TRU-013: create a scoped test secret, permit one capability call, deny wrong tenant/entity/app/environment, rotate while in-flight, revoke and replay job, trigger emergency rotation and vault outage. Verify old version unusable after grace, audit without value, no sentinel in UI/log/AI/export/asset/backup restore, and one authoritative access trace. Do not confuse a Vault pass with a successful Asset lifecycle test.
