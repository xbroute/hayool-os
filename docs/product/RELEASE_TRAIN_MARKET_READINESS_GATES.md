# Hayool OS — Release Train & Market Readiness Gates
Version: 7.2 overlay (V6 detail adopted)
Status: Adopted normative detail; subject to V7.2 resolutions and release mapping

## Principle
V1 is a product vision, not one giant launch.

Each V1.x release must produce usable value and evidence for the next.

Targets below are release-control targets and may be adjusted through ADR/owner decision as real baseline data emerges.

## V1.0 — Hayool Internal Alpha
Purpose:
Operate Hayool's own workflows.

Must have:
- top internal workflow journeys mapped and usable
- tenant/auth/permission baseline
- projects/tasks/client/contracts
- finance foundation
- talent/people foundation
- audit
- backup/restore rehearsal
- no known P0/P1 release blockers
- browser QA Persian RTL
- project profitability traceability.

Success evidence:
team uses it for real internal operations rather than demo-only data.

## V1.1 — Design Partner Beta
Purpose:
Prove multi-company usefulness.

Requirements:
- multi-tenant isolation tests
- onboarding
- plan/entitlement baseline
- export
- support
- tenant branding
- minimum docs.

Recommended:
3–5 controlled design partners.

Measure:
- time to first value
- weekly usage
- critical workflow completion
- support burden
- retention intent.

## V1.2 — Talent Network Beta
Purpose:
Prove managed supply/demand.

Requirements:
- structured profiles
- work graph
- matching
- invite/apply
- compensation corridor
- trust/safety
- dispute
- privacy
- fair-exposure policy.

Measure:
- fill rate
- time to shortlist
- acceptance
- completion
- dispute
- repeat work
- new-talent exposure.

## V1.3 — Workforce Architect Beta
Purpose:
Prove that Hayool can help design capacity, not only fill jobs.

Requirements:
- business discovery
- capability map
- work inventory
- build/buy/automate/hire
- scenarios
- human edit/approval
- shadow evaluation.

Measure:
- manager acceptance/edit rate
- scenario usefulness
- cost/capacity improvement where measurable
- recommendation errors.

## V1.4 — Managed Workforce Beta
Purpose:
Hayool becomes commercial counterparty in selected engagements.

Blocked unless:
- legal mode approved
- contracts approved
- payment/payout process
- classification process
- dispute
- working-capital policy
- insurance/partner responsibilities understood.

Start narrow by jurisdiction.

## V1.5 — Intelligence Beta
Purpose:
Ask Your Company + forecast + Digital Twin.

Requirements:
- semantic metrics
- analytical read models
- provenance
- decision ledger
- baseline forecasting
- uncertainty.

Forecast gate:
candidate model must outperform or add measurable value over baseline.

## V1.6 — Commercial GA
Requires:
- security hardening
- DR/restore tested
- upgrade tested
- Cloud/Dedicated/On-Prem process
- docs
- SLA/support operation
- country pack quality
- billing/licensing
- AI credit accounting
- observability
- incident runbook
- legal/privacy artifacts
- customer export/offboarding.

## Post-GA expansion
Only after initial ICP shows retention:
- new vertical packs
- new country packs
- broader network
- enterprise ecosystem/connectors.


## V1.7 — Universal Operations Platform
Purpose:
Prove that the kernel extends beyond professional services without core rewrite.

Requirements:
- Hayool Studio baseline
- custom objects/forms/workflows
- sales/procurement/inventory baseline
- provider/capability registry
- Intent-to-Outcome baseline
- Retail/Distribution/Field Service starter packs
- import/export/migration center
- mobile/barcode workflow baseline.

## V1.8 — Physical Operations / Industry Beta
Purpose:
Validate real-world physical operations.

Requirements:
- Light Manufacturing starter
- Asset/Maintenance
- Logistics/Delivery
- Agriculture/Food starter
- Edge/IoT connector architecture
- traceability.

Do not call regulated industry packs GA without separate readiness.

## V1.9 — Global Platform GA
Purpose:
Commercialize extension platform.

Requirements:
- Studio packaging/rollback
- industry-pack maturity system
- country-pack capability matrix
- extension SDK
- partner/certification policy
- global localization/accessibility baseline.


## V1.10 — Ecosystem & Developer Platform GA

Purpose:
Make external/community development a supported product path rather than an internal experiment.

Requirements:
- Developer Portal
- public API/event stability policy
- SDK
- CLI
- test tenant
- private app install
- declarative solution package
- remote app pattern
- scoped app permissions
- protected-data disclosure
- version/update lifecycle
- signed packages
- marketplace registry
- publisher verification
- app analytics/health
- extension compatibility CI
- capability request/bounty baseline
- pricing/AI-cost governance in place.

Gate:
At least three non-core sample/partner applications must be built without modifying protected Core.
At least one must survive a platform upgrade compatibility test.
