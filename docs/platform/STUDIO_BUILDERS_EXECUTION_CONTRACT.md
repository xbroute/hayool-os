# Studio schema, form/view and rule/workflow contracts

Status: specified V1.7, with the scoped schema/package foundation separately proved at V1.1 (REQ-EXT-013). REQ-EXT-002 owns custom record/schema persistence, REQ-EXT-018 owns accessible form/view authoring, REQ-EXT-019 owns deterministic pure rules and authorized workflow execution; their TEST IDs are independent. Studio is extensibility for ordinary and nonprogrammer builders, not a privileged back door into Ledger, tenancy, Vault or country policy.

Schema: tenant/app namespace, version, typed field/relation, field ACL, purpose/retention, index/query budget, migration plan and rollback/forward recovery. Form/view: input validation, role-specific projection, keyboard/screen-reader/fa/en preview, draft/publish approval, field permission at server query and command boundaries, previous submission rendering. A hidden field is not only hidden in the UI. Rule: parsed bounded deterministic AST with CPU/memory/depth/row quotas, stable clock/currency semantics, no arbitrary I/O, net/shell/eval, and typed commands only. Workflow: versioned transition, actor/approver, idempotency, timeouts/retry, audit and compensating action when external side effect is uncertain. AI builder may create only a reviewed draft (REQ-EXT-003).

`TEST-REQ-EXT-002`: two-tenant schema upgrade/record migration with conflicting field grants and rollback. `TEST-REQ-EXT-018`: an independent nonprogrammer authors an accessible fa/en form and role view; wrong role cannot submit or infer a protected field. `TEST-REQ-EXT-019`: duplicate event, stale approval, unbounded expression, attempted Core I/O and failed external action; no privilege gain or double side effect, recoverable versioned trace. GJ-04 must show all three and extension upgrade survival; elapsed builder time is measured, not presumed.
