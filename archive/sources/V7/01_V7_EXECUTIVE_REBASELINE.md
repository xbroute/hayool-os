# Hayool OS V7 — Executive Rebaseline

## 1. North Star

Hayool OS coordinates intent into outcomes across people, AI, suppliers, assets, work and transactions, while allowing businesses and partners to extend the platform without modifying the protected core.

Canonical loop:

Intent
→ Goal / Need
→ Capability
→ Work
→ Resource
→ Assignment / Commitment
→ Execution / Fulfillment
→ Transaction / Finance
→ Evidence
→ Outcome
→ Learning.

This loop is the product. Modules are views over this loop.

## 2. Why V7 is necessary

V6 correctly established Clean Core, Studio, Developer Platform, Marketplace/Partners, rational AI and global packs. V7 closes the remaining execution gaps:

- broad architecture vs narrow commercial wedge;
- absence of a jurisdiction-resolution engine;
- absence of authoritative project-state and next-action ledgers before code;
- risk of using documentation as a substitute for evidence;
- risk of implementing all verticals first-party;
- incomplete formalization of global provider availability, sanctions/export restrictions, data residency and workforce mobility;
- lack of one unified outcome/evidence gate across engineering, market, finance, legal, accessibility and ecosystem readiness;
- stale historical milestone wording that can confuse autonomous agents.

## 3. Non-negotiable product principles

1. Work/Capability precedes static job title.
2. Human, team, vendor, asset, automation and digital worker can share planning abstractions while retaining distinct legal/security semantics.
3. Financial, authorization, entitlement, payroll, tax and money state are deterministic.
4. No public race-to-the-bottom talent bidding.
5. No opaque universal worker score.
6. No invasive surveillance by default.
7. Cross-tenant raw data/learning is off by default.
8. AI is optional for core correctness.
9. No silent self-modifying high-impact production policy.
10. Customer/industry specificity prefers extension over Core.
11. Architecture may be broad; external claims must reflect verified maturity.
12. A milestone is an outcome proof, not a module count.
13. No country is “supported” because its locale renders; support requires legal, financial, provider and operational evidence.
14. No external provider is assumed universally available.
15. No legal rule is activated solely because an AI agent found it on the web.

## 4. Product completeness model

Completeness has five independent dimensions:

### Design Completeness
The domain, invariants, boundaries, policies and extension points exist in Source of Truth.

### Implementation Completeness
The behavior exists in code and migrations.

### Verification Completeness
Tests, security checks, browser flows and restore/upgrade evidence pass.

### Jurisdiction Completeness
Applicable country/subnational/industry/legal/provider policies are validated and effective-dated.

### Market Completeness
Real users achieve the intended outcome with acceptable retention, support burden and unit economics.

A feature may be 100% designed and 0% market-ready. The system must say so.

## 5. Product architecture

### Protected Core
Tenancy, identity, permissions, audit, entitlements, financial ledger, authoritative inventory movements, policy framework, extension permission boundary, event contracts and platform safety primitives.

### Universal Business Kernel
Parties, organizations, locations, catalog, resources, work, commercial commitments, documents, approvals, time, finance events, physical flows, outcomes and evidence.

### Hayool Studio
Governed custom objects/fields/relations/forms/views/workflows/reports/dashboards/portal surfaces/solution packages.

### Developer Platform
Public capability APIs, events, SDK, CLI, test tenant, manifests, scopes, app principals, protected-data declarations, Remote Apps, package lifecycle and compatibility testing.

### Country/Subnational Packs
Tax, payroll, invoicing, banking/payment conventions, labor policy, privacy/data residency, accessibility, AI rules, identity/address formats, holidays and local providers.

### Industry Packs
Terminology, domain objects, workflows, integrations and compliance constraints that reuse the kernel.

### Intelligence Layer
Rules, retrieval, optimization, prediction, semantic decisions, generative agents, digital twin and controlled learning.

## 6. Commercial wedge

Initial ICP remains project-based digital/professional-service companies.

First golden journey:

Client Need
→ Discovery
→ Requirements
→ Scope
→ Estimate
→ Price
→ Contract
→ Project
→ Capacity / Team
→ Execution
→ Client Acceptance
→ Invoice / Collection
→ Project Profitability
→ Outcome / Retrospective.

The first product must make this journey excellent before first-party vertical breadth becomes a priority.

## 7. Long-term category

Do not lead early sales with “software for everything.”

Corporate category:
**Extensible Business Operating Platform**

Initial category:
**Operating System for project-based companies**

Developer story:
**Build once. Extend Hayool. Reach businesses.**

General experience:
**Tell Hayool what needs to happen.**

## 8. Owner-level moat

Hayool should build three compounding moats:

1. **Outcome Graph Moat**
   Work + resource + cost + time + quality + transaction + outcome.

2. **Extension Ecosystem Moat**
   Builders, developers, industry experts, country partners and integrators solve customer demand without Core becoming the bottleneck.

3. **Governance/Trust Moat**
   Companies can adopt AI and automation without giving up deterministic truth, auditability, human review, data isolation, reversibility or global policy controls.

## 9. Anti-goals

Hayool is not:
- a module-count competition;
- an AI chatbot with ERP screens;
- an EAV database disguised as a platform;
- a universal legal/compliance claim;
- a plugin runtime that executes arbitrary untrusted code inside the main API;
- a marketplace that maximizes price compression;
- a surveillance platform;
- a system that depends on one AI/provider/region.

## 10. V7 operating rule

Every proposed capability is classified before implementation:

A. Core primitive  
B. First-party pack  
C. Studio solution  
D. Low-code component  
E. Pro-code extension  
F. Integration adapter  
G. Partner/regulatory system boundary  
H. Future/experimental.

This classification is required in the REQ/ADR before implementation.
