# Hayool OS — Owner Decision Sheet
Version: 6.0

These are proposed defaults. M0 may challenge them with evidence, but should not silently reverse them.

| ID | Decision | Proposed default |
|---|---|---|
| OD-001 | Long-term category | AI-native Extensible Business Operating Platform |
| OD-002 | Initial ICP | Project-based digital/professional service companies |
| OD-003 | Brand | Hayool OS masterbrand; Studio/Marketplace/Network are product surfaces, not separate brands by default |
| OD-004 | Universal model | Work + Resource + Transaction/Outcome graphs |
| OD-005 | Core policy | Clean Core; customer/industry specificity prefers extension over Core |
| OD-006 | Extensibility | Configuration → Studio → Low-code → Pro-code Extension → Core |
| OD-007 | Developer ecosystem | SDK/API/Events/CLI/Test Tenant are V1 platform capabilities |
| OD-008 | Marketplace | Partner/community registry begins in V1; public commercial expansion is security/maturity gated |
| OD-009 | Extension runtime | Declarative + Remote Apps first; untrusted hosted runtime only after security maturity |
| OD-010 | Bidding | No public price-underbidding race for talent |
| OD-011 | Worker scoring | No opaque universal human score |
| OD-012 | Monitoring | No invasive surveillance by default |
| OD-013 | Cross-tenant learning | Off by default; aggregated/opt-in only |
| OD-014 | Hiring/termination | Human review default for high-impact employment |
| OD-015 | Managed workforce launch | Managed Team/Marketplace before broad EOR/AOR |
| OD-016 | Custody | No custody/escrow claim without legal/payment infrastructure |
| OD-017 | Product architecture | Modular monolith first |
| OD-018 | Deployment | Cloud + Dedicated + On-Prem from one codebase |
| OD-019 | Packaging | Clear base plans + modules/packs + AI Credits; avoid unpredictable SKU explosion |
| OD-020 | AI billing | Hayool Credits + optional BYOK |
| OD-021 | AI usage | AI only with explicit value/cost justification; core remains usable with external AI disabled |
| OD-022 | Talent matching | Constraints + multi-objective + fair exploration |
| OD-023 | Self-learning | Controlled promotion, never silent self-modification |
| OD-024 | Pricing objective | Management chooses objective and hard margin floors; AI cannot redefine them |
| OD-025 | Profit policy | Distinguish gross/contribution/fully-loaded margin from accounting net profit |
| OD-026 | Pricing experiments | Allowed only inside defined cohorts/ranges with guardrail metrics and audit |
| OD-027 | Developer economics | Marketplace revenue share/take rate is tested, not hard-coded from intuition |
| OD-028 | Open-source strategy | Public SDK/spec/examples preferred; commercial Core may remain proprietary |
| OD-029 | Regulated systems | Technically extensible, but market/certification claims remain explicit and partner/jurisdiction gated |
| OD-030 | Industry expansion | Architecture broad; first-party/marketing readiness follows pack evidence |
