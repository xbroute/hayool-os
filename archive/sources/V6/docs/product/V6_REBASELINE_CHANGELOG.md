# Hayool OS — V6 Rebaseline Changelog

## Why V6 exists

V5 made Hayool a Universal Business Platform but still implied too much first-party vertical development.

V6 changes the expansion strategy:

**Hayool Core no longer owns every industry requirement. The platform owns the extension system.**

## Major changes

### 1. Developer Platform promoted to first-class V1 scope
Added:
- SDK
- CLI
- Developer Portal
- event catalog
- test tenant
- app manifest
- app permissions
- remote app architecture
- marketplace lifecycle.

### 2. Extensibility model formalized
Configuration
→ Studio
→ Low-code
→ Pro-code
→ Core.

### 3. Clean Core policy
Third-party/customer code cannot patch Core.

### 4. Community economics
Marketplace, capability requests, bounties, partner program and developer revenue become product strategy.

### 5. AI discipline
Added AI Necessity Gate and fully loaded AI cost ledger.

AI-native now means “use the right intelligence engine,” not “put LLM calls everywhere.”

### 6. Pricing system upgraded
Added:
- margin vocabulary
- manager-defined floors
- fully loaded cost
- Pricing Lab
- controlled experiments
- AI-credit pricing optimization
- marketplace pricing economics.

### 7. Brand/category refinement
Long-term:
AI-native Extensible Business Operating Platform.

Initial GTM:
Operating System for project-based companies.

### 8. Regulated vertical clarification
Highly specialized systems can be built by partners/extensions.
Market/certification responsibility remains explicit.

### 9. Ecosystem Moat
Strategic moat now explicitly includes:
- Outcome/Data Graph
- Developer/Partner Marketplace.

### 10. M0 obligations
M0 must prove extensibility before large new vertical buildout.
